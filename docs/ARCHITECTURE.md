# Architecture

How CuiSharp is put together and which rules must not be broken. Read this before changing the
binding, the runtime or anything that ships in a package.

Measured cost per frame: [PERFORMANCE.md](PERFORMANCE.md). Release notes: [../CHANGELOG.md](../CHANGELOG.md).

## Decisions

Settled. Reopening one is a design change, not a refactor.

| # | Decision |
|---|---|
| D1 | `Ui` and every scope are `ref struct`. They cannot be stored, captured by a lambda, boxed, or held across `await`. |
| D2 | **The native library is pristine upstream.** `native/CUI/` is a pinned submodule and is never edited; `native/patches/` is empty on purpose. Anything native belongs upstream — the earlier local patches (window chrome, translucent background) were withdrawn because a local copy of upstream behaviour drifts on every sync. |
| D3 | Four packages: `CuiSharp` (core + analyzers + `Hosting` + `Semantics`), `CuiSharp.Testing`, `CuiSharp.Tools` (`dotnet cui`), `CuiSharp.Templates`. Hosting, testing and tools all live above a core that knows nothing about them. |
| D4 | `net10.0` only, `LangVersion=latest`. No legacy targets, no shims. |
| D5 | Bindings are generated by `tools/bindgen.cs` (a file-based C# program using libclang). Generated code is checked in and must be byte-identical on every machine. |
| D6 | Breaking changes are allowed until 1.0. `docs/API-SURFACE.txt` is the approval file: a change is a diff in review. |
| D7 | No runtime reflection, no assembly scanning, no interceptors. Every call path is statically visible so NativeAOT can trim it. |
| D8 | **A packaged native library declares the ABI it was built against.** Windows x64/ARM64 is `/MT` MSVC, Linux x64/ARM64 is glibc 2.31 built inside `debian:11`, `osx-arm64` targets macOS 12. `native/build-native.sh` fails rather than emit a `libcui.so` that needs more, and the Linux build runs inside that image so it cannot inherit a newer floor; the package records the revision, compiler and hashes it shipped (`runtimes/native-provenance.txt`), and `build/CuiSharp.targets` matches the RID exactly and errors when the archive for it is missing. See [native-abi.md](../skills/cui-dotnet/native-abi.md). |
| D9 | **Window behaviour the framework needs is a hook over CUI's own window procedure, not a native patch.** A drag on Windows makes Win32 send `WM_SIZE` per mouse sample and then a `WM_PAINT` that invalidates the whole client area, and CUI draws in both, inside the modal loop, with vsync on: one mouse step cost two frames and two display waits. `Hosting/LiveResize` subclasses the window procedure (the one place Windows lets a framework intervene), lets the coalesced paint draw once, and stops waiting for the display for the length of the drag — driving CUI's own live-frame path rather than replacing it. The same hook is where the window handle is recovered for `CuiWindow`, because the app loop keeps its `cui_app*` private and the window's user data holds it. A fix that needed `native/CUI/` would be upstream's, per D2. |

## Binding pipeline

```
native/CUI/include/cui/*.h
  -> tools/bindgen.cs  (libclang from NuGet; struct layout queried per RID)
  -> bindings/api.json              functions, structs, enums, constants, icons, doc comments, sizes/offsets
  -> + bindings/overrides.json       the only hand-written input: exceptions, each with a "why"
  -> Interop/Native.g.cs            [LibraryImport] per C function
     Interop/Structs.g.cs           blittable structs (bool -> byte, pointers -> nint)
     Interop/Enums.g.cs             enums, shared C prefixes removed
     Interop/Constants.g.cs         anonymous-enum values
     Ui/Options.g.cs                friendly option structs + allocation-free ToNative()
     Ui/<Section>.g.cs              one `extension(Ui ui)` block per header section
     Ui/ScopeEnds.g.cs              which native end-call closes which begin-call
     Ui/Records.g.cs                array item types (Choice, TableColumn, ...)
     Icons.g.cs                     embedded glyphs
     Tests/Abi.g.cs                 sizeof and every field offset, asserted
     Tests/OptionMappings.g.cs      one test that every option maps every field
     skills/cui-dotnet/{llms.txt,api/*.md}, bindings/coverage.txt
```

The convention table the generator's default rules implement:

| C | C# |
|---|---|
| `cui_foo_bar`, `cui_foo_bar_ex` | `FooBar(UiText label, ..., FooBarOpts o = default)` |
| `const char *` parameter | `UiText` (one overload for `string`, `"utf8"u8` and `$"…"`) |
| `const char *const *items, int count` | `ReadOnlySpan<string> items` |
| `const float *v, int count` | `ReadOnlySpan<float> v` |
| `char *buf, size_t cap` | `ref string value` over a pooled buffer |
| `bool *` / `int *` single value | `ref bool` / `ref int` |
| `float *pos` (non-const, one value) | `ref float pos` — the widget moves it |
| `x_begin` returning void/id + `x_end` | `LayoutScope X(...)` — `using` closes it |
| `x_begin` returning bool + `x_end` | `OpenScope X(...)` — `Open`, `implicit operator bool` |
| result flags (`CUI_CHANGED`, …) | `readonly struct` (`InputResult`) when the bits are shared and read one by one |
| a widget's own event or action word | the `[Flags]` enum or enum it names (`PlayerEvents`, `TourAction`) |
| `CUI_TONE_DANGER` | `Tone.Danger` |
| header comment | `/// <summary>` |

An array is a `const` pointer, and a widget that writes one value back through a pointer says so
with a non-const one: `float *pos` is the compare divider, not a list of positions. That is why
the plural-name heuristic in `Parameter()` is narrowed to const pointers — `pos` and `progress` end
in an `s` and are still one number.

An `int` return is the last thing callers should have to decode. When the header documents it as
one of `CUI_TOUR_*` or a `CUI_PLAYER_*` word, the wrapper returns that enum (`returnTypes` in
`overrides.json`), because the alternative is a call site comparing against a constant it has to
reach into `Interop` for — and, for the tour, mistaking the action for the step it returns beside.

Adding a wrapper to the hand-written layer instead of the generator is allowed, but it must be
recorded in `bindings/overrides.json` as `MANUAL` with the member and the file, because
`coverage.txt` claims that nothing wraps it otherwise.

Record array counts derive only through explicit `recordFieldCounts` overrides identifying
input-only metadata (`QueryField.Choices`, `ApiEndpoint.Params`, `UptimeService.Days`,
`StackFrame.Source`, `FilterField.Options`). An output count is information, so declaration shape
alone never hides it. `GridState` owns managed grid state; `GridScope` owns stable frame-arena
copies of the pointers CUI retains through its rows and writes them back on open and on close.
Forwarding managed fields or stack locals at begin would leave native with dangling pointers.

## Core rules

- `public ref struct Ui` wraps the native context. One `Ui` per frame, passed by value; the only
  things stored between frames are the app's own fields plus per-frame arenas and pools.
- `LayoutScope` (always open) and `OpenScope` (conditional) are `ref struct` + `IDisposable`, so
  `using` balances them even when the body throws. `GridScope` is the conditional scope with
  end-of-body write-back; the scope analyzers treat it like `OpenScope`. Every `OpenScope` also has a callback overload
  that runs the body only when it is open.
- `UiText` accepts `string`, `ReadOnlySpan<byte>` and interpolated strings; the handler formats
  with `IUtf8SpanFormattable` straight into the frame arena, grows on demand, never truncates, and
  allocates nothing per frame.
- One overload per widget. No `Textf`, no separate `u8` methods.
- `ui.Id(key)` / `ui.Keyed(items, key)` push an id scope; a widget id inside a loop must come from
  the item, which is what `CUI004` enforces.
- Text inputs: `ref string` plus a per-id pooled buffer; encode only when the managed string
  changed, decode only on the frames the native widget reports a change.
- Charts decimate over `ChartOpts.MaxPoints` (default: chart width × 2) into the arena;
  `SeriesDecimator` is public for custom canvases.
- `[assembly: DisableRuntimeMarshalling]`, `IsAotCompatible`, `IsTrimmable`.
- `[SuppressGCTransition]` only on the reviewed allowlist in `overrides.json` — leaf functions that
  cannot call managed code and cannot block.
- A `Localization` table is the one managed object CUI keeps a pointer into across frames. Three
  rules follow from that and are enforced, not documented and hoped for: the surface that published
  it owns it and a second surface is refused (only the owner republishes a block a name change
  replaces); a replaced or orphaned block is freed at the next frame boundary, never inside the frame
  that dropped it, because the frame still drawing reads it; and a name edited after the call is
  published by the surface at its boundary, which is what makes one `ui.SetLocalization` enough.

## IDE code fixes

Code fixes are a separate `netstandard2.0` assembly, shipped beside the analyzers in the core
package. Workspaces belongs to the IDE and is unavailable to command-line compilers (RS1038), so
it must never become an analyzer or runtime dependency. CUI002 adds `using`; conditional scopes
also get a guard. CUI003 guards only the using statement's body, or the remainder of a using
declaration's block. A rewrite that introduces a compiler error is not offered. Scope fix-all
is deliberately unavailable until overlapping body edits can be applied sequentially. CUI005
removes only an awaited BCL `Task`/`ValueTask.ConfigureAwait(bool)`, not a look-alike method, a
configured awaitable stored in a local, or `ConfigureAwaitOptions` (which can suppress exceptions).
CUI004 wraps a widget in an id scope on its actual receiver, and a using declaration together with
its remaining children. It only chooses a foreach item or an integer counter incremented/decremented
by the same for loop; nested loops, while/do loops and ambiguous keys require a manual rewrite.
No fix-all is offered. Display-only text and calls addressing an existing id are not row collisions;
labels used to animate widgets (Gauge, Meter, ProgressRing) still need distinct keys.

## Frame model

`CuiApp.Run(options, draw)` hands the loop to CUI, which registers a frame callback. That callback
is what the OS modal loop also invokes while a window edge is dragged, which is why the window owns
the loop: a managed `while` loop is blocked during the drag and the layout would go stale.

Each frame, in order: `Completions.Drain()` (work that finished on a pool thread is applied on the
UI thread), `Component.BeginFrame()`, `FrameStats.Begin()`, the root component renders, `FrameStats.End()`,
then `ui.RequestRedraw()` if a mutation is running or a component reported `WantsFrames`, because a
sleeping window cannot be woken by a pool thread. Finally `PendingWork.MarkDrawn()` spends the owed
wake-up, so the loop can sleep again.

`FrameStats` measures the frame that just drew, so a footer needs no clock of its own. `DrawMs` and
`AllocatedBytes` cover the component's own draw — CUI's layout and paint happen after it — so
`AllocatedBytes` reading 0 is a statement about app code. `FrameMs` is wall clock, which means an
idle app reports the gap since it last woke; `Fps` therefore only averages runs of frames and
`IsLive` says whether the app is in one. `CuiSurface.LastFrame` is the same sample for one surface,
which is what a test asserts on: the process-wide statics are only right for one window.

The theme is CUI's, not the app's: `ui.Theme` and `ui.Accent` read it and assign it, `ui.ToggleTheme()`
flips it, and CUI animates every colour token across the change on the frames that follow. There is
no dirty flag to keep.

`CuiSurface` runs the same draw code with no window, driving frames by hand: that is what the
tests, the benchmarks, the snapshots and `dotnet cui` use.

There is no synchronization context, no dispatcher and no `TimeProvider` today. `Mutation` applies
its result through `Completions`, and that is the whole async story: continuations do not run on the
UI thread, they hand a value over at the next frame boundary.

## Native callbacks

A `void (*)(…)` argument crosses into native code from managed code in exactly one way:
`Runtime/FrameCallbacks.cs` puts a delegate in a `Holder` kept alive by a `GCHandle`, keyed and
reused, records the handle per thread, and frees it at the next `Utf8.BeginFrame()`. Handing C a
managed object address is never allowed. This is what unlocks `ui.TreeTable(...)` events and
`ui.State<T>(id, onFree)`.

## Semantics (recording, tree, query)

Recording is off by default and costs one inlined null test per widget. A `CuiSurface` owns a
`FrameRecorder` (not the thread), so two apps in one test keep their own frames; the thread-static
in `WidgetRecorder` is only a pointer to the surface drawing right now, restored at `EndFrame`.

A container is a node when the app named it — a `Card`/`Box`/`Scroll` with an `Id`, or a
`Dialog`/`Menu`/`Table` whose first argument is its title. It records itself through the scope it
returns, so the record knows where the container ends. Unnamed containers are not nodes, but their
children still nest under the nearest named one and `Depth` reports the real depth.

A widget that draws one control per item — a tab strip, a segmented control — records the strip as
a container and each item as a control (`Tab "Markets"`, `Segment "Dark"`), because the item is what
a click lands on. CUI derives an item's id from its index and the widget's id
(`cui__hash(&k, sizeof k, id)`) and does not expose it, so `CuiHash` mirrors that function, and
`WidgetRecordingTests` proves the mirror by clicking a recorded item on a real surface. Everything
else about an item comes from CUI as usual: the item's rectangle is read at `EndFrame`, like any
other widget's.

Text is read out of the frame arena when the frame ends, not while it draws, so recording never
makes a frame allocate. The snapshot itself is data that outlives the frame, so it does allocate —
outside the window `FrameStats` measures.

`SemanticNode` rebuilds that nesting; `WidgetQuery` is the vocabulary a search uses (a label, a
kind and a label, or a path) and it ranks: exact before prefix before substring, and an actionable
control before static text at the same tier.

## Tests

`CuiSharp.Tests` covers the library (the generator's contract, ABI, option mappings, frame
lifecycle, allocation budgets, analyzers, the recorder and the query language). The template's own
test project is the pattern an app copies: rules in the small, a ring buffer, a simulator with a
fake clock, and `PageRenderTests`/`PageInteractionTests`, which draw real frames with no window,
click through them and assert 0 B per frame. The template is verified the way a user meets it —
`pwsh tools/verify-template.ps1` packs, generates, builds, tests, publishes, checks that the
package's analyzer fires and drives the result with `dotnet cui`.

## Headless protocol

`HeadlessLoop` serves one command per line and answers `CUI-OK <bytes>` / `CUI-ERR <bytes>` followed
by exactly that many payload bytes and a newline. The byte count is what makes a label containing
anything round-trip. The reader re-synchronizes on any line that is not a header, so an app may
print whatever it likes: its output goes to stderr and the protocol stays clean.

The tool stays a relay: it builds (or reuses a published build), starts the app headless, sends
one command, prints one answer, and gets out of the way. It is deliberately not a test framework,
not a session manager and not a hot reload integration — `CuiSharp.Testing` is the fast, repeatable
way to drive an app from an agent, and `dotnet watch` is how a human edits in place. Anything that
would need a stateful daemon belongs in the testing driver, not here.

An app opts in by running headless (`CUISHARP_HEADLESS=1` or `--headless`). `CuiApp.Run` is the only
place that decides, and a hosted app reaches it with its host's draw callback, so a tool drives the
same frame a window would. The feature is a `[FeatureSwitchDefinition]`, so a binary that does not
want the channel can trim it out with `CuiSharp.Headless=false`.

Both ends are bounded, because a protocol is a trust boundary: a command line over 64 KiB is
answered as an error instead of read, an answer over 16 MiB is refused with its size, the client
keeps only the tail of the app's stderr and never accumulates a line without a newline, and a
timeout says which wait it gave up on — the banner or the answer.
